# Project Review — 2026-11-25

This pass examines the observed hosted CI failures and the CLI installation/update paths.
It is not an assertion that every module or supported GPU backend is production ready.

## Fixed findings

- **High — recovery data loss:** updater cleanup deleted staging (including original-file
  backups) even when rollback failed. Failed restores now retain the recovery directory,
  report its location, and attempt restoration of the remaining files. Keyboard interrupts
  also enter rollback. This does not provide recovery from power loss or SIGKILL.
- **High — relocated catalog lookup:** a release binary used absolute catalog paths from
  the build runner or preferred an old source checkout. Lookup now checks the installation
  relative to the actual executable before development fallbacks; an explicit catalog
  environment override retains precedence.
- **High — clean installation failure:** a clone made with `--no-checkout` has tracked
  files missing, which the installer mistook for user modifications. A shallow clone now
  materializes a clean worktree before fetching and checking out the pinned commit.
- **Medium — modified pinned source:** the cleanliness check ran only when HEAD differed
  from the pin, allowing modified code at the correct revision to be built as “pinned.”
  The check now runs on every build.
- **Medium — missing CI runtime dependency:** Linux CTest grep-tool cases failed because
  ripgrep was absent. CI and release workflow prerequisites now explicitly include it;
  macOS provisioning also declares it.

## Evidence

The fresh-clone regression uses a local Git repository with an older pinned commit and a
newer default branch. It verifies the pinned contents, then modifies the checkout and checks
that the next build refuses it without discarding edits. CMake is stubbed for this test;
it does not establish that all llama.cpp backends compile.

Updater fault injection checks interrupt rollback, continued restoration after a failure,
backup retention, and successful replacement. CLI integration copies the executable into
a different prefix with a distinct catalog and checks that the installed catalog wins.

All three CMake presets built and passed 10/10 CTest cases. Python suites passed 41 benchmark
tests and 9 installer/updater tests. Shell syntax, Python compilation, formatting, and diff
whitespace checks passed.
